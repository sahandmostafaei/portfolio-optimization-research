# Reproducibility

## Objective

This project is structured so that the empirical analysis can be reproduced
from the documented methodology and source code.

## Environment

The analysis is implemented in Python.

Required Python packages are listed in:

`requirements.txt`

The recommended Python version for the validation workflow is Python 3.11.

## Repository Structure

- `data/` — Data documentation and data requirements
- `docs/` — Research integrity and reproducibility documentation
- `figures/` — Empirical figures
- `methodology/` — Research design
- `paper/` — Research manuscript
- `results/` — Empirical result tables and outputs
- `src/` — Reproducibility code

## Data

The baseline implementation obtains historical market data for the ETF
universe specified in the research design.

The baseline universe is:

- SPY
- EFA
- EEM
- TLT
- GLD
- DBC
- VNQ

The analysis uses adjusted historical prices to construct return series.

## Baseline Parameters

The baseline empirical specification uses:

- 60-month rolling estimation window
- Monthly portfolio rebalancing
- Long-only portfolios
- Fully invested portfolios
- Maximum 30% weight per asset
- No leverage
- No short selling
- 15 basis points transaction costs

## Portfolio Strategies

The baseline comparison contains four portfolio construction strategies:

1. Equal Weight
2. Global Minimum Variance
3. Mean-Variance Optimization
4. Equal Risk Contribution

## Information Timing

At each portfolio formation date, estimation uses only information available
through that date.

Portfolio performance is evaluated over the subsequent period.

This lag structure is intended to prevent look-ahead bias.

## Execution

From the repository root, install the required dependencies:

`python -m pip install -r requirements.txt`

Then execute the research script:

`python src/portfolio_research_reproducibility.py`

The script requires access to historical market data in order to perform the
empirical analysis.

## Validation

The repository includes a GitHub Actions workflow that verifies:

- required project files exist;
- the Python source compiles successfully;
- project dependencies can be installed.

The validation workflow is intended to verify the research environment and
source code. It does not manufacture, fabricate, or publish empirical
findings.

## Empirical Outputs

Empirical results should be added to the `results/` directory only after the
research pipeline has been executed successfully.

Figures generated from the empirical analysis should be stored in the
`figures/` directory.

Results should remain traceable to the source code, methodology, data, and
parameter assumptions used to generate them.

## Reproducibility Standard

A result should be considered reproducible only when another researcher can
identify:

1. The research methodology
2. The source code
3. The required data
4. The parameter assumptions
5. The execution procedure
6. The resulting output

Changes to the methodology, data treatment, or parameterization should be
documented.

## Research Integrity

No numerical finding should be reported as an empirical result unless it has
actually been generated by the research pipeline using historical data.

The project distinguishes between the research design and the completed
empirical analysis. This distinction is maintained until the analysis has
been executed and independently checked.
